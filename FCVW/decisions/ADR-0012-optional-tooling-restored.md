# ADR-0012: Tooling is optional again

## Context

[ADR-0001](ADR-0001-pure-markdown-over-automation-scripts.md) promises that the clean package has no required runtime dependency. From V0.14.0 to V0.19.0 the mandatory change flow broke that promise: every plan change had to regenerate `QUEUE.md`, every added or moved document had to regenerate `DOCUMENT_GRAPH.md`, and the instructions asked for `ROLE_MANIFEST.json` to be regenerated after file changes. A team without Python could not complete a change without leaving a stale versioned file behind.

## Decision

No versioned artifact is generated by a tool. The plan queue is derived from plan frontmatter ([PLANNING.md](../PLANNING.md)), reachability from the files themselves ([ADR-0011](ADR-0011-record-reachability.md)), and `ROLE_MANIFEST.json` is a release baseline that only the upgrade tool replaces. The tools, which need Python 3.10 or later and only the standard library, check and accelerate the contracts but are never required to finish a change.

## Consequences

- ADR-0001 holds again: every mandatory step can be done by hand.
- Derived views (queue, graph, index) live only in `.fcvw-cache/` or a caller-chosen path.
- Validation claims still state whether they came from a tool or from manual review.
