# V0.24.0 publication

## Description

Publish V0.24.0 from the reviewed content: commit the content baseline, produce and review the four language variants, mark the release ready, tag, package, verify and publish the GitHub Release, then record the evidence.

## Justification and objective

The implementation plans are complete and validated in the source checkout; nothing is published. Publication needs the maintainer's authority and the language work that `RELEASE.md` requires.

## Scope

### Included

- Content baseline commit and `source_revision`.
- `pt-BR`, `en-US`, `es` and `de` variants: reuse the V0.23.0 translations line by line where the English text is unchanged; translate the changed lines (the sections listed under "Framework surfaces changed" in the release record).
- Language review records, packaging, checksums, tag and release; lock advanced to `ready`, then `published`.

### Excluded

- Any functional change: a defect found here reopens the matching implementation plan.

## Affected files or boundaries

`FCVW/framework-releases/V0.24.0.md`, `FCVW/FRAMEWORK_LOCK.md`, `README.md` (badges and links), `TODO.md`, external release staging and assets.

## Implementation plan

1. Commit the reviewed content; record its revision as `source_revision`.
2. Build the four variants in external staging; run `locale_fcvw.py --require-complete --source-root <clean export> --source-revision <revision>`.
3. Run `check_fcvw.py` with at least two interpreters; add a Linux run if available.
4. Mark the record and the lock `ready`; tag; build with `package_release_fcvw.py`; verify each archive with `verify_release_fcvw.py --run-tests`; rebuild to confirm reproducible checksums.
5. Publish; record publication evidence; set the lock and the record to `published`.

## Proportionality gate

Not applicable — release procedure only, no new mechanism; every step is an existing gate of `RELEASE.md`.

## Acceptance criteria

- [x] Four variants pass `locale_fcvw.py --require-complete` with approved language reviews.
- [x] Each archive passes `verify_release_fcvw.py --run-tests`; a second build reproduces the checksums.
