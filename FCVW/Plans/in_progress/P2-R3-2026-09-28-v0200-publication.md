# V0.20.0 publication

## Description

Publish V0.20.0, which carries phases 1 to 3 of the maintainer backlog, as four language-specific clean templates. The maintainer authorized publication after phase 3.

## Justification and objective

Installed projects receive nothing until the release is published. The release contract requires an immutable content baseline, four reviewed language variants with machine and structure parity, deterministic assets with external checksums, a ready commit, and publication evidence.

## Scope

### Included

1. Content-baseline commit, including a correction of stale packaging statements in `RELEASE.md`.
2. `pt-BR`, `es` and `de` variants built from the published V0.19.0 translations (unchanged sections reused) plus AI-assisted translation of new text; one approved `LANGUAGE_REVIEW.md` per variant naming the baseline.
3. `locale_fcvw.py --require-complete`, packaging, `SHA256SUMS.txt`.
4. Ready commit: release record and `FRAMEWORK_LOCK.md` set to `ready`.
5. Tag and GitHub Release, and the post-publication evidence commit, as far as the available tools allow.

### Excluded

Framework behaviour changes; disabling GitHub Pages (repository settings, not versioned content).

## Affected files or boundaries

`FCVW/RELEASE.md`, `FCVW/framework-releases/V0.20.0.md`, `FCVW/FRAMEWORK_LOCK.md`, root `README.md` version surfaces; external staging and assets outside the repository.

## Implementation plan

Follow the framework release steps of `RELEASE.md` in order.

## Proportionality gate

- Real problem: an unpublished release reaches no project.
- Existing solutions reused: `locale_fcvw.py`, `package_release_fcvw.py`, `verify_release_fcvw.py` and the V0.19.0 translations.
- New code: none.

## Acceptance criteria

- [ ] The locale gate passes for all four variants against the external source export.
- [ ] Four ZIPs and `SHA256SUMS.txt` are built and each installed payload passes verification.
- [ ] The release record and lock agree on the published state only after real publication.
