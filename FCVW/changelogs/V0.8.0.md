## Justifications

- Priority and risk classifications needed operational consequences for predictable plan handling.
- Application module documentation needed a formal downstream convention without reintroducing framework-owned `docs/` artifacts.
- Agent journals needed one wiki-owned path to avoid fragmented operational memory.

## Affected Files

- Framework planning, audit, workflow, AI/wiki governance, agent skills, reusable templates, version metadata, and session records.

## Functional Impact

- No runtime product behavior changes.
- AI agents now have clearer operational gates before starting plans.
- Downstream applications now have a documented path and templates for module documentation.
- Agent journals now have a single official wiki location.

## Visual Impact

- No UI changes.

## Technical Impact

- Plans must include operational score, review gate, rollback requirement, and decomposition requirement.
- `R4` and `R5` plans require rollback and expanded validation; `R5` also requires explicit human approval.
- Filled application module documentation belongs to the downstream application-owned root `docs/` folder when applicable.
- Agent journal paths are `FCVW/wiki/agents/<agent_name>_journal.md`.
