# FCVW V0.15.0

## Summary

In-preparation framework update for evidence-backed plan dependencies, typed source-aware knowledge, and a contained single-folder installed filesystem.

## Related framework plans

- [Plan dependencies and typed knowledge](../Plans/completed/P2-R4-2026-08-21-plan-dependencies-and-typed-knowledge.md)
- [Single-folder release layout](../Plans/completed/P2-R4-2026-08-21-single-folder-release-layout.md)

## Framework surfaces added

- Dedicated plan-dependency inspection plus disposable typed knowledge graph and stale-review generation through bounded tools.
- Tracked-source wiki template and optional aggregate plan-queue output.
- Deterministic source-to-installed layout mapper for removable release assets.

## Framework surfaces changed

- Planning, schemas, memory, AI, tests, filesystem, ownership, audit, context routing, plan/wiki templates, queue validation, context indexing, retrieval, release packaging/validation, and affected existing skills.

## Framework surfaces removed

Root-level release payload copies of `tools/`, `LICENSE`, `NOTICE`, provider bridges, repository `README.md`, and `.gitignore`. Both canonical queues, the document graph, BM25, JIT routing, and existing schema majors remain.

## Ownership and path changes

The new Python tools are framework-owned. In V0.15.0 release assets, all framework filesystem content is contained under root `FCVW/` except `AGENTS.md`; installed tools therefore live at `FCVW/tools/`. Physical containment does not change preservation ownership for populated profiles and records. Generated knowledge graphs, source-review reports, context indexes, and aggregate queue views are disposable and excluded from distribution.

## Schema changes

`fcvw/plan@2` gains optional `depends_on` plus a conditional dependency-evidence table. `fcvw/wiki@1` gains optional maturity, typed relations, and source provenance. `fcvw/knowledge-graph@1` is a derived JSON schema, not canonical data.

## Migration

Follow [V0.14.0 to V0.15.0](../MIGRATIONS.md#v0140-to-v0150). Active queue-only blockers migrate to plan metadata and evidence rows; untouched terminal history remains readable. Existing installations reconcile old root framework paths against the prior manifest and never bulk-delete ambiguous application files.

## Validation

Implementation validation passed locally: 92 unit tests; source and materialized installed clean-template validators errors=0/findings=0; installed payload root exactly `AGENTS.md` + `FCVW/`; installed document graph nodes=198/findings=0; knowledge graph errors=0/findings=0; all Python ASTs valid; and no diff whitespace errors. Publication-only language, asset, checksum, immutable revision, and release evidence remain intentionally pending.

## Downstream preservation rules

Preserve all populated plans, queues, wiki pages, source records, digests, and review history before replacing or removing `FCVW/`. Merge new optional fields deliberately, reconcile pre-V0.15.0 root paths individually, and regenerate only disposable outputs.

## Known gaps

No production wiki corpus exists in the clean baseline, so semantic-review precision and retrieval recall improvements require downstream measurement. Semantic review remains optional. Language-specific assets are not yet built, so the contained layout is validated through deterministic fixtures rather than claimed as published binaries.

## Rollback

Restore V0.14.0 framework-owned policies, templates, root tools, and package behavior while retaining project records. Remove generated cache outputs. Do not delete same-named application root paths or rewrite plan/wiki history.
