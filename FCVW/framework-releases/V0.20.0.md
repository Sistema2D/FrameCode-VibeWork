# FCVW V0.20.0 — ready

## Summary

Phases 1 to 3 of the source-only maintainer backlog (`TODO.md` at the source repository root, not installed). Phase 1 (integrity, prepared as [V0.19.1](V0.19.1.md) and folded in here) stops the upgrade from overwriting unverifiable local edits, closes validator loopholes and routes project profile edits away from the framework policy route. Phase 2 removes empty and redundant files and folders, takes the inactive experiment layer out of the core, derives the plan queue and document reachability instead of versioning them, and adds guards against regrowth. Phase 3 fixes triggers on the reduced structure: paths imply only facts and application changes declare their semantic events, discovery is exact, ADRs are validated, skill triggers live in the description, and the documents drop per-version history. No verifiable rule was lost. The last published baseline is V0.19.0; this record is the ready candidate built from content revision `438c477bf3ee88c4330520f18b82926ba27e5031`.

## Framework surfaces added

- `FCVW/PROJECT.md` (`fcvw/project@1`): the single project profile, with per-section `not_applicable_sections` waivers.
- `REFACTORING_GUIDE.md`, `governance/TEMPLATE_NOTE.md`, `TEMPLATE_APP_DOC.md`, `TEMPLATE_SKILL_CHANGE.md`: consolidations of the guide folder and fragmented templates.
- `upgrade_fcvw.py --prune`: removes framework files dropped upstream that still equal the installation baseline.
- Validator rules `profile-legacy`, `plan-queue-legacy` (warnings) and `clean-scaffold-directory`; `fcvw/adr@1` registered in `SCHEMAS.md`.
- Validator rule `adr-schema`: ADR id, status, filename, title and `superseded_by`.
- `retrieve_context.py` routes-only mode (no `--index`/`--query`) and a `warnings` list when a versioned application change declares no semantic event.
- Tests: frozen rule-ID inventory (117 IDs), surface budget, template-envelope uniqueness and a 23-case path-to-event table.
- [ADR-0010](../decisions/ADR-0010-core-reduction.md) (core reduction), [ADR-0011](../decisions/ADR-0011-record-reachability.md) (record reachability) and [ADR-0012](../decisions/ADR-0012-optional-tooling-restored.md) (tooling optional again).

## Framework surfaces changed

- Policies: `AUTOMATION.md` absorbs hooks, watchers, daemons and gates; `RELEASE.md` absorbs versioning; `INSTANTIATION.md` absorbs retroactive instantiation; `AI.md` absorbs the token budget; `OWNERSHIP.md` absorbs the filesystem layout; `PLANNING.md` absorbs the plans README; `wiki/README.md` becomes the single wiki contract.
- Skills: `governance-validator` 2.0.0 (with the former `agnix-linter` and `wiki-lint`), `wiki-curator` 2.0.0 (with the former `aicc-compact` and `memory-rotation`); the briefing questionnaire moves into `project-instantiation`; product-wiki guidance and templates move into `QA`.
- Tools: queue derived from plan frontmatter (`plan_queue_fcvw.py` rewritten); reachability through record directories; declarative record specifications and one fence tracker in the validator; role-based policy routing; the installed payload no longer carries framework history.
- Phase 3 changes: path-derived events limited to file operations, framework surfaces, AI bridges and `.github/workflows/`; exact matching for the operational index, skill catalog and session routes; `trigger_keywords` optional and deprecated, with every skill description stating when to use it and when not (patch version bumps); `SCHEMAS.md` limited to versioned artifacts; a trivial prose fix needs no plan; ADR-0006, 0008 and 0009 marked superseded by ADR-0010; root README cut from 690 to 249 lines.
- Phase 1 changes: `upgrade_fcvw.py` safe mode and truthful JSON, `role_manifest_fcvw.py` refusing to overwrite an installed baseline, validator fixes (legacy plan state, troubleshooting schema, `--since` scope, pending results).

## Ownership and path changes

Project-owned truth moves into `PROJECT.md`; the old profiles are preserved by the upgrade and reported until merged. Framework history (`record_scope: framework`) stays in the source repository and shipped policies link to it by repository URL. The old-to-new path table is in the [migration note](../MIGRATIONS.md).

## Schema changes

- New: `fcvw/project@1`. Newly registered: `fcvw/adr@1` (already used by every ADR).
- Retired: `fcvw/plan-queue@1`, `fcvw/plan-queue-entry@1`; optional plan fields `category`, `blocked_external` and `before_in_progress` replace them. `fcvw/document-graph@1` is derived on demand and never versioned.
- `fcvw/plan@1` is accepted only in `completed/` and `discontinued/`; troubleshooting records must declare `fcvw/troubleshooting@1`.
- `fcvw/adr@1` is now validated; ADRs without an envelope are reported as warnings only. `fcvw/skill@1` no longer requires `trigger_keywords` (deprecated).

## Migration

See the V0.19.0 to V0.20.0 section of the [migration note](../MIGRATIONS.md). Rehearsed on a materialized V0.19.0 installation with application records, filled and pending profiles and two locally edited framework policies: after `--apply --prune`, all 20 project-owned files kept their SHA-256 digests; 172 unmodified framework files were pruned (39 framework history records, 35 policy and guide files, 47 templates, 28 scaffolding files, 9 tools, 6 generated files, 4 skills and 4 examples); the edited dropped policy was kept for review and the edited replaced policy left a `.local` backup. Every new validator finding after the upgrade is one of the documented manual steps.

## Validation

The full source suite, clean-template governance, the labeled retrieval benchmark and installed-layout smoke tests pass through `check_fcvw.py` on Linux with Python 3.10, 3.11, 3.12 and 3.13; evidence is in the phase 2 and phase 3 plans (280 tests in the final run). Windows and macOS were not exercised.
