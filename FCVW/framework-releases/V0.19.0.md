# FCVW V0.19.0 — in preparation

## Summary

Free, explicit local validation replaces the unavailable hosted workflow. Multidisciplinary QA adds mandatory first-use application mapping, sourced behavior knowledge and selective live testing. The published baseline remains V0.18.0.

## Framework surfaces added

[Loop evaluation](../governance/LOOP_EVALUATION_CONTRACT.md): strict frozen protocol
and event schemas, optional local aggregation, paired descriptive reports, external
evidence templates and regression tests. Existing retrieval is unchanged; incomplete
usage, interrupted runs, shadow attribution and independent-review limits remain visible.


Local check runner, failure/evidence regression tests and [local execution contract](../governance/LOCAL_VALIDATION_CONTRACT.md).

[QA profile](../skills/QA/SKILL.md), target-specific execution guidance, product inventory/surface/run templates and an optional selected-page coverage checker. Expected behavior stays separate from observed results, with hashes preventing reuse of an old pass against a changed contract.

## Framework surfaces changed

QA 1.1.0 requires a user question for every behavior divergence, with 100%
consultation coverage and zero pending decisions before dependent actions. Its
checker derives missing questions from failed cases and preserves historical
outcomes even after the user chooses a direction. Run templates and product
documentation record the question, answer reference and selected direction.

Current automation/test documentation, README and inventories; hosted automation contract retired.

## Framework surfaces removed

Source-only automatic GitHub Actions workflow.

## Ownership and path changes

Tools remain framework-owned; reports are disposable local cache or external evidence. No project-owned paths move. Filled product wiki and QA records are application-owned and preserved; the clean framework ships guides and templates only.

## Schema changes

Optional disposable local-validation JSON contains environment, command logs, results and source identity. Canonical Markdown major schemas are unchanged. Optional wiki QA metadata/tables cover GUI and non-GUI surfaces and runtime provenance; they are checked only when explicitly selected.

## Migration

See [migration note](../MIGRATIONS.md). No account, service, credentials or background runner required.

## Validation

228 source and installed tests passed on Windows/Python 3.12 and 3.14; governance and the labeled benchmark pass. All four existing V0.18.0 archives passed 219 tests per runtime against matching source. An initial Windows temporary-directory cleanup failure was retained in evidence; an explicit repeat passed. No hosted or Linux execution is claimed.

The subsequent QA increment passes 242 source and installed tests on Windows/Python 3.12 and 3.14, plus governance and the labeled benchmark. An isolated browser/CLI replay maps 10 elements and six cases, preserving one deliberate defect alongside five passes. The full-validator local median changes from 438.012 to 449.111 ms; the optional two-surface checker takes 1.518 ms in-process. These small samples are not performance guarantees. No downstream app, native desktop, Linux, C++ or physical firmware execution is claimed. See the completed QA plan for external evidence and the corrected initial template-test failure.

The subsequent mandatory user-decision increment passes 249 source and installed tests on Windows/Python 3.12 and 3.14, plus governance and the labeled benchmark. Seven new decision tests cover unasked/pending/answered cases, invalid evidence, partial consultation and provisional intent. A preserved historical failure correctly reports one pending user decision; a user's chosen direction does not turn it into a pass.

The loop-evaluation increment passes 273 source and installed tests on Windows/Python
3.12 and 3.14, plus governance and the existing labeled benchmark. Its 24 new tests
cover metric math, missingness, resumed evidence, false completion, QA decisions,
provenance, bounded inputs and output paths. The separate 24-audit repository pilot
preserves a failed experimental gate: one pilot-forbidden public catalog proposed
in shadow, plus budgeted UI useful recall falling from 1.0 to 0.5. Actual mandatory
recall stays 100%; actual forbidden hits stay zero. Provider tokens and independent
review are unavailable; these audits do not establish real-agent task efficacy or
authorize issues 56/57. See the completed loop plan for evidence and scope limits.
