# FCVW V0.14.0

## Summary

Release-ready framework revision implementing the governance and tooling approved from open issues #42 through #48. Four independent monolingual empty-template variants were generated from immutable source revision `c9ac95ce7255e19828212193b3084e4078214050`; their accountable language reviews are approved and all structural, graph, clean-template, adversarial, and approved-package gates pass. ## Framework surfaces changed

- Planning, schemas, ownership, context routing, audit, governance gates, tests, release, versioning, migration, filesystem, AI, application documentation, and instantiation policies.
- `anti-monolith-guard` and `code-hygiene-refactor` advanced to `1.2.0` through the self-improvement gate.
- Application and framework release templates now share GitHub-oriented assets, checksums, migration, validation, rollback, and publication-evidence sections.
- Troubleshooting records now have a typed, scoped, source-linked contract; Markdown fence and source-relative link validation no longer accept examples or absolute paths as real relationships.
- Retrieval now fails when mandatory context is absent, assigns unique accent-normalized chunk IDs, and never infers an undeclared framework language.
- Release validation binds checksums to exact language assets, rejects repository/editor state and non-Markdown drift, and enforces content-versus-publication lifecycle revisions.
