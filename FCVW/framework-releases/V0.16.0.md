# FCVW V0.16.0

## Summary

Remediation of the independent V0.15.0 audit. The release fixes defects in the
published asset, converts gates that existed only as prose into rules the
validator executes, reduces validation cost and noise in large repositories, and
replaces the shared queue file with one fragment per plan.

No existing schema was narrowed, so V0.15.0 installations remain valid without
retroactive editing.

## Related framework plans

- [`P2-R4-2026-08-28-audit-remediation-and-scale-hardening`](../Plans/completed/P2-R4-2026-08-28-audit-remediation-and-scale-hardening.md)

## Framework surfaces added

- `FCVW/governance/TEMPLATE_PLAN_COMPACT.md` — the proportional form that
  `PLANNING.md` promised and no tool accepted.
- `FCVW/governance/TEMPLATE_CI_WORKFLOW.md` — copyable Scenario 3 reference
  workflow, never installed by implication.
- `FCVW/ROLE_MANIFEST.json` — the role manifest `OWNERSHIP.md` required.
- `FCVW/tools/role_manifest_fcvw.py`, `FCVW/tools/upgrade_fcvw.py`,
  `FCVW/tools/fcvw_cache.py`.
- `FCVW/Plans/{pending,in_progress}/queue.d/` — queue fragments.
- `FCVW/wiki/feedback/` — attributed surface for an AI model's feedback about the framework itself, with `FCVW/wiki/templates/TEMPLATE_FEEDBACK.md`.

## Framework surfaces changed

- `validate_fcvw.py` — new `character-integrity`, `language-review`,
  `automation-contract`, `plan-compact`, `plan-risk-binding`, and
  `plan-rollback` rules; suppression of derived noise from a stale catalog;
  `--format json`, `--fail-on`, and `--since`.
- `document_graph_fcvw.py` — lexical link resolution instead of syscall-based
  resolution.
- `plan_queue_fcvw.py` — fragment reading and `--write-queues`.
- `locale_fcvw.py`, `package_release_fcvw.py`, `release_layout_fcvw.py` —
  provider bridges at the root and the manifest treated as a per-variant
  generated surface.
- Structural suites — correct root resolution in the installed layout and
  assertions over controlled values instead of localizable prose.
- `FCVW/refactoring-guide/` — six reproduced catalog files consolidated into
  `02-refactoring-catalog.md`.

## Framework surfaces removed

- `FCVW/refactoring-guide/02-composing-methods.md`,
  `03-moving-features-between-objects.md`, `04-organizing-data.md`,
  `05-simplifying-conditional-expressions.md`,
  `06-making-method-calls-simpler.md`, and `07-dealing-with-generalization.md`.
  They transcribed public literature, cited their own source, and carried no
  FCVW policy.

## Ownership and path changes

- `.cursorrules` and `.windsurfrules` return to the repository root, where their
  editors actually read them. The removal boundary becomes `FCVW/` plus the
  explicit review of `AGENTS.md` and the two bridges.
- Records with `record_scope: framework` under project-owned directories are now
  classified as `framework_history`, so an upgrade can replace them instead of
  leaving them as permanent project history.
- `Plans/<state>/QUEUE.md` becomes a generated surface when `queue.d/` exists;
  without the directory it remains a preserved project profile.

## Schema changes

- Added `fcvw/plan-compact@1`.
- Added `fcvw/plan-queue-entry@1`.
- Added `fcvw/role-manifest@1`.
- `fcvw/plan@2` now requires a non-empty `Rollback`, refuses
  `regression_contract: not_applicable` at risk `R3` or above and in plans
  routed through `SECURITY.md`, `DATA.md`, or `MIGRATIONS.md`, and requires a
  justification of at least 40 characters.
- `fcvw/automation@1` is now validated.
- `fcvw/wiki@1` gains `type: feedback` with `authored_by_model`, `topic`, and `feedback_status`; a note never overwrites another model's note and states its own suggestion before assessing prior ones.

## Migration

See [`MIGRATIONS.md`](../MIGRATIONS.md), section V0.15.0 to V0.16.0. The
migration is additive: no existing artifact needs rewriting, and adopting
fragmented queues is incremental.

## Validation

- `python -B FCVW/tools/test_validate_fcvw.py` — 102 tests.
- `python -B FCVW/tools/test_open_issues.py` — 67 tests.
- `python -B FCVW/tools/test_plan_dependencies_and_knowledge.py` — 9 tests.
- `python FCVW/tools/validate_fcvw.py --root . --profile clean-template` —
  `errors=0 warnings=0 findings=0`.

Two of the three suites failed in the V0.15.0 installed layout; all three pass
in this version.

## Language-variant parity and review evidence

Every variant was remediated in this preparation, and
`FCVW/LANGUAGE_REVIEW.md` was rewritten in each one to name
the language it declares. The new `language-review` rule prevents the defect
from recurring.

## Downstream preservation rules

Project profiles, application plans, changelogs, audits, briefings,
troubleshooting, and project-created wiki pages remain preserved.
`python FCVW/tools/upgrade_fcvw.py --root . --release <target>` runs a dry run
and refuses to overwrite a locally modified framework policy without
`--accept-conflicts`.

## Known gaps

- Derived surfaces are still eight independent artifacts; unifying them into one
  representation with projections remains open.
- The on-disk graph cache was deliberately refused on proportionality grounds;
  suppressing derived noise solved the signal problem without a new
  invalidation surface.
- The mandatory reading route grew by roughly 7.5 percent, because machine-checkable
  gates had to be documented in `PLANNING.md` and `SCHEMAS.md`.
